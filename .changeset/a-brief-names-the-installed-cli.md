A task brief names the installed CLI and the shipped doctrine, never a path that exists only in the repository that authors this package. Every brief an adopter received told its Developer to read the Developer doctrine at `aeg-root/roles/developer.md`, to re-derive dispatch readiness with `bun packages/aeg-core/bin/verify-dispatch.ts`, to check documentation coverage with `verify-docs.ts --pr`, to open the pull request with `bun apps/cli/src/index.ts pr create`, and to start the body from `aeg-root/templates/pr-report-template.md` — five things an `npm install` of this package puts nowhere the reader can reach. One Developer that received such a brief read it as spoofed instructions and stopped; another worked around it.

The renderer now takes the repository's own CLI invocation as a fact and writes every command it names through it: `npx --yes @attalabs/vinaya@<version>` where the CLI is installed from the registry, and the vendored source entry where the repository carries the CLI as a workspace member — the same decision, over the same detection, that the generated hooks and workflows already make, so a brief and a hook in one repository can never disagree about how the CLI is reached. The invocation is never defaulted: a render with none refuses and names the missing fact, the same as a missing source revision.

The two documents a brief used to name by path are now named as commands that print them out of the installed package: the Developer doctrine as `vinaya doctrine --role developer --print`, which already existed, and the PR report as `vinaya doctrine --template pr-report --print`, which is new — `--template` resolves a shipped template through the same doctrine root `--role` uses, enumerates the valid names off disk rather than from a list, and refuses being combined with `--role` rather than silently preferring one.

Where a repository ships an unabridged derivation of a gate the brief names — this one's `verify-dispatch.ts` and `verify-docs.ts`, which cover the prior-tranche-archival predicate and the spec-status/code-requires-docs contracts that the shipped checks do not — the brief now names the shipped check first and that derivation after it, as a fact about the repository rather than as the only command on offer. A repository that ships neither gets the shipped checks alone.

The rewrite reaches the Planner's own prose too, not only the commands the renderer writes: a `vinaya <args>` span in a Traps, Boundary, Stop-and-escalate or Test plan field is rendered through the same invocation, so a command a task author spelled the short way is still runnable where the brief lands. `## Objectives` is the one section held out — a gate compares it to the Issue word for word. A vendored member is named only once its source entry is confirmed present, since the detection matches on the member's package name and says nothing about its layout; a repository whose member carries no such entry gets the registry invocation rather than a brief of commands pointing at a file that is not there. Section 2 now asks the Developer to confirm dispatch readiness with the command section 5 names, instead of naming an output string only this repository's own unabridged derivation prints.
