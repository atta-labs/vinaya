The evaluation harness gains its module registry: a catalog entry for every module of the evaluation program, and component rows that each state the ten required fields, name one catalog module and only that module's suites, and are refused with a typed reason when a field is empty, a placeholder or names an unknown module or suite. Rows live in shard files found by listing their directory, and aggregation refuses a duplicate component id naming both locations. The first shard covers the core ports, the engine nodes and transitions, and the register's product guarantees, and a completeness check derives each of those universes from its typed source. The registry is internal and does not ship.
