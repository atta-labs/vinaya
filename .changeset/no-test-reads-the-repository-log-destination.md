No CLI test reads the repository's own log destination, and a push that changes the repository-root `vinaya.config.json` runs the whole CLI suite. Two `checks/runner/cancelled.test.ts` cases spawned the check runner inside this repository and then read the default local log folder under a temporary `$HOME`: because a spawned command resolves its configuration by walking up from its own working directory, they were reading a destination the repository's own `logs` setting could empty out from under them — declaring a `logs.url` there made both fail. They now spawn against a fixture configuration of their own (`isolatedConfigFixture`, the configuration half beside `process-fixture.ts`'s existing environment and kill-budget halves: a temporary `$HOME`, a working directory holding an empty `vinaya.config.json` where the resolution walk stops, and an explicit `AEG_REPO` so the destination path is asserted rather than discovered by listing the runtime root), with every assertion unchanged. `log-destination-isolation.test.ts` is the mechanical backstop, in the shape `process-fixture-coverage.test.ts` already established: every fixture that reads a default log destination must name a working directory for the processes it starts, or be listed by path — and the list is empty. The pre-push selector never caught the original break because it selects by import graph and no test imports a root configuration file; it now returns the whole CLI suite for a push that changes the repository-root `vinaya.config.json` — that file is an input to every command a test spawns, so a configuration change can no longer pass pre-push and fail in CI.
