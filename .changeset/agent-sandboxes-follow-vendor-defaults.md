A confined Claude Code dispatch's sandbox now follows Claude Code's own documented default: commands read the machine except five named credential locations (`~/.ssh`, `~/.aws`, `~/.config/gh/hosts.yml`, `~/.codex/auth.json`, `~/.claude/.credentials.json`), denied through `sandbox.credentials.files` in `deny` mode — never a blanket read-deny over the whole real `HOME`/temp root, and never a hand-made grant for a linked worktree's shared `.git` (Claude Code's own sandbox already allows that). `gh *`, `git push *`, `git fetch *` and `git pull *` are excluded from the sandbox, with matching `permissions.allow` rules so they run unprompted in a non-interactive dispatch, as Claude Code's own documentation prescribes for Go-based CLIs and for git's network commands on macOS; `allowUnsandboxedCommands` stays `false`. The sandbox's allowed-domains list is always the one fixed list this module owns (`CLAUDE_SANDBOX_ALLOWED_DOMAINS`), never assembled per task, with `network.strictAllowlist: true` — GitHub, the npm registry, and now also `api.anthropic.com`, the agent vendor's own API host, so a sandboxed subprocess that itself shells out to the model API (never the unconfined main process, which reaches it directly) is not refused.

A confined Codex dispatch's run-scoped `CODEX_HOME` now holds only a copy of `auth.json`, the run's own `config.toml` and the run-scoped `rules` directory — no other entry of the operator's real `~/.codex` is symlinked in. Its config.toml sets the top-level `web_search = "live"` key, independent of the sandboxed-command network domain rules, so a confined Codex Developer can read official documentation through live web search. `GH_TELEMETRY=0` already rode every dispatched role's environment (Claude and Codex alike) before this change; this task confirms and documents that.

Under Claude Code, the Developer now publishes its own work: it commits, pushes its task branch and opens or updates its own pull request itself, holding its own forge credential — the driver no longer commits, pushes or opens the pull request for it. The driver still does all three for Codex, whose `workspace-write` sandbox keeps `.git` read-only by design. `buildRolePermissions('developer')` grants `git push`/`gh` (previously revoked) for exactly this reason; this permissions file is Claude-only, so a Codex dispatch is unaffected (`PERMISSION_POLICY_VERSION` moves to `v6`: `git push`, `git pull`, `git fetch` and an enumerated set of `gh pr`/`gh issue` subcommands, never a blanket `gh` grant). The task worktree is fast-forwarded to the current default-branch head, alongside its already-moved remote branch, before the first Developer turn, whenever the branch carried no commits beyond main — so the Developer never starts from a stale commit.

`apps/cli/specs/isolation.md` and `aeg-root/roles/developer.md`/`developer/reference.md` are updated to describe both boundaries and who publishes per agent in these terms, dropping the prior round's whole-home read-deny description.
