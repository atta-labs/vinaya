Every run state now has one Operator action that works, and the doctrine says which. Until now the Operator's doctrine named `task_start` for "a task that has never been dispatched" and `task_resume` for "a paused or exited run" — but `task_resume` refuses any run with no pause record. So a driver that was killed, crashed, or ended by a signal mid developer dispatch left a state with no tool that worked at all, and the Operator correctly stopped and asked rather than improvising. `task_start` now refuses a run only when the tool it names in its place would actually move it. A live driver belongs to `task_status`, decided by the same derivation `task_status` reports from. Every other refusal is decided by the pause record itself rather than by the reported state, because a pause whose driver is then killed reports as an exited run while its record still holds it — reading the state name alone let that pause be started straight past the Principal ruling it was still waiting for. A held pause is five answers, not one: a pause still awaiting a decision belongs to `task_resume` behind its Principal ruling — load-bearing rather than cosmetic, since `task run` itself continues a paused task from its pause and would otherwise walk straight past that ruling — while a pause already ruled on whose driver then died, and a recoverable infrastructure hiccup the loop resumes without a ruling of its own, are both continued by `task_start`, because `task_resume` launches nothing for either; a pause already resolved as cancel is refused by both and says so, and a pause record or resolution that cannot be read is refused rather than guessed past, since a record that will not parse might be the cancellation the refusal exists to protect — and a truncated pause record read as no pause would restart the run as a fresh dispatch rather than a resume. The infrastructure waiver is bounded the same way the loop bounds it, because past that bound the loop accepts any older ruling already on the pull request rather than requiring a fresh one. A pause a later published round has already superseded holds nothing and starts normally. Every other state launches, including an exited one: `task run` re-attaches to the task's own open pull request whenever no driver is live, so starting an exited run continues it rather than opening a second one. The Operator's doctrine gains a state-to-action table over every state `task_status` can report — whose paused row names `task_start`, the one action that never silently does nothing there, since `task_resume` answers `already_resumed` without starting anything for a pause already ruled on — and a conformance test parses that table out of the doctrine file the CLI serves, checks its state column against the loop states the code can actually produce, and drives each state — built as real files and read back through the shared derivation — through the tool that row names, so the two cannot drift apart again. The doctrine's duration rule is narrowed rather than dropped: a promise, a deadline, or an estimate the Operator formed stays forbidden, while a typical time a status read itself returns from this repository's recorded history may be passed on, labelled as history and carrying its sample count.
