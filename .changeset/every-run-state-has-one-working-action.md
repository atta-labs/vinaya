Every run state now has one Operator action that works, and the doctrine says which. Until now the Operator's doctrine named `task_start` for "a task that has never been dispatched" and `task_resume` for "a paused or exited run" — but `task_resume` refuses any run with no pause record. So a driver that was killed, crashed, or ended by a signal mid developer dispatch left a state with no tool that worked at all, and the Operator correctly stopped and asked rather than improvising. `task_start` now reads the task's loop state through the same derivation `task_status` reports from, and refuses a state only when the tool it names in its place would actually move the run. A live driver belongs to `task_status`. A paused run is four answers, not one: a pause still awaiting a decision belongs to `task_resume` behind its Principal ruling — load-bearing rather than cosmetic, since `task run` itself continues a paused task from its pause and would otherwise walk straight past that ruling — while a pause already ruled on whose driver then died, and a recoverable infrastructure hiccup the loop resumes without a ruling of its own, are both continued by `task_start`, because `task_resume` launches nothing for either; a pause already resolved as cancel is refused by both and says so. Every other state launches, including an exited one: `task run` re-attaches to the task's own open pull request whenever no driver is live, so starting an exited run continues it rather than opening a second one. The Operator's doctrine gains a state-to-action table over every state `task_status` can report, and a conformance test parses that table out of the doctrine file the CLI serves, checks its state column against the loop states the code can actually produce, and drives each state — built as real files and read back through the shared derivation — through the tool that row names, so the two cannot drift apart again. The doctrine's duration rule is narrowed rather than dropped: a promise, a deadline, or an estimate the Operator formed stays forbidden, while a typical time a status read itself returns from this repository's recorded history may be passed on, labelled as history and carrying its sample count.
