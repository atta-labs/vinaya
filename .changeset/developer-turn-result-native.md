The Developer's turn result now arrives as each CLI's own structured final output — Claude Code through `--json-schema`, Codex through `--output-schema`, on every first and resumed Developer dispatch — instead of the `.vinaya-confidence` and `.vinaya-round-response` files the Developer's sandbox often could not write. A lost confidence no longer pauses a round whose work was already published. The driver alone accepts the result: it checks the finding ids against the round's handoff (now listed in the prompt as `R<round>-CR-<n>` and `R<round>-SEC-<n>`), the fields against the round and status, a ruling request against the permissible decisions, and every required Documentation source against a counted read. Each attempt is recorded once under the round's Developer folder. A rejected result is sent back to the same session once with only its failures, and a second rejection pauses the round. A `blocked` or `needs_ruling` result pauses it for the Principal. The confidence rule, the Log's `gate_result_read` fields, the round marker comment (which now also shows the Developer's reported checks, as context only) and `vinaya task status`'s last confidence read the accepted result. `task-tools result-proof` replaces its forced Stop-hook case with the controller rejecting a result that misses a required source, then accepting the corrected one from the same session. Gemini has no native structured output, so a Gemini Developer turn now pauses the round, naming that.
