A pull request counts as a concluded review only while its ready-for-merge summary is posted AND the review gate passes against its current head, objectives version, newest Principal ruling, frozen brief and policy. A summary table records no head, so the summary alone was sticky: a summary posted for an older head kept reading "done forever" through a red gate, a ruling posted after it, a superseded brief and a moved head, refusing every `vinaya dev-review-loop --resume` and restarting round numbering at 1 on the next run. `reconstructRounds` now takes the gate's verdict as an input fact beside the summary fact, one predicate (`isConcludedJournal`) serves all three readers of "is this concluded?", and the gate is evaluated in-process through the same input assembly the `review-gate` check itself builds — never a second hand-built copy, and never by shelling out to `vinaya check`. A reopened pull request keeps its round history: the next round is numbered after the last round marker on the forge and the published summary table carries every prior round. A review that IS concluded is still refused on resume, now with a message that says so (`loop already concluded at round <n> (summary posted <url>)`) instead of the unrelated consumed-resolution text; a live driver on a task still refuses exactly as before.
