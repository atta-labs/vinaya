'@attalabs/test-selection': patch

A file added to or deleted from a folder the recorded run did not list now reaches a test through a listed folder above it only when some folder on its path is absent on the other side: at the earlier revision for an added path, at the later one for a deleted one, whether that folder lies below the listed folder, is the listed folder itself, or lies above it. A new file inside folders that exist on both sides, such as every pull request's `.changeset/` entry, no longer selects every test whose code listed the root, and deleting the whole tree a test listed still selects it. Each added or deleted `PathChange` the selection builds, between the base and the head and between the record's commit and the base alike, carries that folder as `newFolder`, read once from the two revisions' file lists; a change without it walks as before. The dispatch child-process test's survivor check also sends the zero signal again when a process state reads empty, and counts the launch as gone only when that signal fails, so a launch that exits between the zero signal and the state read is no longer counted as running, and a failed `ps` hides no survivor.
