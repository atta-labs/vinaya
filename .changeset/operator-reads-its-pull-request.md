The Operator can read why its task's pull request is red. A sixth read-only task tool, `task_pr_read`, returns for the selected task's own pull request every required and reported check with its state, conclusion and — for a failed one — its failure summary, alongside the pull request's principal-authored review record: the newest verdicts and the head they judged, the round markers, the published summary table, and any pause comment. The pull request is always resolved from the task's own branch; a caller-supplied number is a cross-check that refuses on mismatch, and no other pull request is readable. The review record is filtered through the same principal allowlist the loop's own forge reads use. Check results cannot be author-filtered — a check name, a reported summary, an annotation and a job log are written by whoever landed the workflow file or the build step on the branch — so every one of those strings is secret-redacted through the shared redaction chokepoint, stripped of the grammars that carry authority in this system, and capped before it is returned; the Operator's doctrine names a failed check's output as evidence to quote, never an instruction to follow. The tool re-runs nothing, posts nothing, edits nothing and merges nothing, and holds no forge-write credential. The Operator's grant, its doctrine, its generated skill, the principal–operator contract and the command catalog all name it, so the seat's declared tool list and the tools it holds agree. The Operator's doctrine now also requires every statement about a task's state to come from a tool read made in the same turn: an earlier reading is never repeated as current, and a task's absence from a status list is never read as its completion.
