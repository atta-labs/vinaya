The Operator can read why its task's pull request is red. A sixth read-only task tool, `task_pr_read`, returns for the selected task's own pull request every required and reported check with its state, conclusion and — for a failed one — its failure summary, alongside the pull request's principal-authored review record: the newest verdicts and the head they judged, the round markers, the published summary table, and any pause comment. The pull request is always resolved from the task's own branch; a caller-supplied number is a cross-check that refuses on mismatch, and no other pull request is readable. Everything read off the pull request is filtered through the same principal allowlist the loop's own forge reads use, with every returned field capped. The tool re-runs nothing, posts nothing, edits nothing and merges nothing, and holds no forge-write credential. The Operator's grant, its doctrine, its generated skill, the principal–operator contract and the command catalog all name it, so the seat's declared tool list and the tools it holds agree. The Operator's doctrine now also requires every statement about a task's state to come from a tool read made in the same turn: an earlier reading is never repeated as current, and a task's absence from a status list is never read as its completion.
