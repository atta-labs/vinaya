`vinaya task status` and the `task_status` tool now read every open task truly. A run that published a round's verdicts reads as `published` at that round, not `no driver`: the published-round derivation is one shared reader (`newestPublishedRound`) over the control store's own `readEffect`, treating a round as published only when both its `reviewer-verdict` and `security-verdict` effects read `verified` — the status the executor advances a confirmed post to. Before this, both `task-status.ts` and the task-tools read module globbed a flat `control/effect-<n>-reviewer-verdict.json` for `status: 'posted'`, records the control store had already moved into its `effect/` subdirectory at `verified`, so a published run fell through to `no driver` (observed on the log-server task's own loop). `task_resume` against such a run now refuses naming the published round, instead of a generic refusal. An open, planned task Issue whose brief is not frozen yet is now listed as not started by both the list and single-task forms, never omitted as "no open task matches".
