Every log event names its task, derived from the checked-out branch when the environment does not name one, and events produced inside a repository's own test run are marked as tests. Most of what a log server holds is produced by a `vinaya check` run from the pre-push hook or from CI, which carries no `VINAYA_TASK` at all and so recorded `subject.issue: null` — the event happened on a task's branch, but the record could not say which task. The sink now asks the branch, and only when the environment is silent: `task/issue-<n>` names that Issue directly, and `task/<tranche>/<n>` resolves through the same `vinaya/tranche:<slug>` label and `[<slug>] <n> — …` title parser every other caller already shares. An event whose environment names its task is untouched — the branch is a fallback, never an override — and an unresolvable branch stays `null` rather than a guessed number. The lookup runs at most once per process, lazily (a process whose events already name their task never makes it), caches its answer including a failure, and is bounded by the same deadline the sink's other context lookups carry, so a slow, missing or unauthenticated `gh` delays no event and drops none. Separately, a repository's own tests deliver to the same destination a real run does, so fixture traffic and real traffic were indistinguishable on the server; the test preload now sets a marker the header carries as `meta.test: true`. It is a label, not a switch: it changes nothing about where an event goes, there is no `false` to write — real traffic is said by the field's absence — and the field is optional and additive, so every line written before it existed still validates and no new schema version is involved.
