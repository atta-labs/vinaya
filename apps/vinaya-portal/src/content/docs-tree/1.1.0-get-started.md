## About getting started

Installing Vinaya puts the harness into your repository: its git hooks, its CI workflow and a starter `vinaya.config.json`. From then on, every commit, push and pull request runs the same checks, and every governed act lands in the [Log](/docs/features/log).

The [Vinaya process](/docs/process) comes with it, plugged in by default.

```callout-tip
For a guided walkthrough from an empty repository to your first gated pull request, follow the [Quick start](/start/quick).
```

## How it works

```steps
### Install
Run `vinaya init` in a git repository. It shows you the complete diff first and writes nothing until you confirm. Add `--dry-run` to see the diff and stop.

### Check the install
Run `vinaya doctor`. It reports what is missing or out of date and never writes.

### Keep it current
Run `vinaya upgrade` after a new version. It regenerates only the files Vinaya owns and keeps your settings.

### Remove it
Run `vinaya eject`. It removes exactly what `init` installed, and lists the labels it created for you to remove by hand.
```

Vinaya records what it installed in the `managed` part of `vinaya.config.json`. That record is how `upgrade` and `eject` know what is theirs, so neither touches your own files. See [Setup commands](/docs/features/configuration/setup-commands) for every file and flag.

## Configuration

`vinaya init` seeds a starter `vinaya.config.json`: both `rings` flags set to `true`, an empty `checks`, a starter `briefSchema`, then `managed`. An empty file is already a full harness, so add a key only to change what runs. See [Configuration](/docs/features/configuration).
