Parent: Features

## About configuration

Everything a team adapts lives in one file at the repository root: `vinaya.config.json`. It is plain JSON, reviewed and committed like any other file.

Every key has a default. An empty file runs the full harness, so you add a key only when you want to change what runs.

Each key belongs to one of two owners:

- **The harness**: the generic machinery every process uses, such as where the Log goes and which agent runs. Those keys are on this page.
- **The process**: what a process declares, such as its roles, brief shape and review policy. For Vinaya, see [Vinaya keys](/docs/process/vinaya-keys).

## How it works

```steps
### Install seeds a starter
`vinaya init` writes a starter file and records what it installed in `managed`. See [Setup commands](/docs/features/configuration/setup-commands).

### You add only what you change
Leave a key out and its default applies. An unknown top-level key is dropped.

### Sensitive keys come from the default branch
Keys that decide who may merge, or name a destination or a program an unattended run would follow, are read from the default branch, not from the pull request. A change cannot rewrite its own rules. See [Trust](/docs/features/configuration/trust).

### A machine-wide file adds defaults
`~/.vinaya/config.json` applies to every repository on the machine. Keys that decide what runs or who is trusted are ignored there and honoured only from the committed repository file.
```

## Troubleshooting

```accordion
### My change to a key in a pull request has no effect
Some keys, such as `principals`, `releaseActor`, `reviewPolicy` and `securityScan`, are always read from the default branch. Your change applies once it merges. See [Trust](/docs/features/configuration/trust).

### A key in my global file is ignored
`checks`, `roles`, `principals`, `releaseActor`, `tokens` and `runtimeDir` are stripped from `~/.vinaya/config.json`, with one warning naming the file. Set them in the repository's `vinaya.config.json`.

### Validation fails on `logPublish`
`logPublish` was removed. Use `logs` to set where events go.

### How do I check my config is valid?
Run `vinaya doctor`. It validates `vinaya.config.json` and reports install drift, trust settings and more, without writing.
```
