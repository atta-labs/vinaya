# Studio — definition

Summary: The web app that reads the record: work in flight, measures over time, and every repository one owner governs. It reads; it never decides.
Parent: Features
Badges: Web app · Read-only · Local · Reads the Log

## About Studio

Studio is the harness's reader. It shows you what your runs did, using only what was recorded.

It answers three kinds of question:

- **Work in flight.** What is happening, for how long, and who must act.
- **Over time.** The ten questions the Log exists to answer, plus a confidence comparison, as statistics and conclusions.
- **Across repositories.** Every repository one owner governs, on one page.

Studio is a harness feature. It reads the Log contract, which is the same for every process. Its screens speak the Vinaya process's vocabulary: rounds, verdicts, pauses, tranches and the nine derived statuses described in the [Overview](/docs/process).

## How it works

Studio has two inputs:

- **The Log, for execution history.** Studio reads Log events and nothing else to know what ran. The Log is a log server or the local log folder. Where a generic family has no event of its own, Studio works it out from the events that exist. See [Events](/docs/process/events).
- **The forge, for presentation only.** Task titles, kinds, pull request state, merge state and who merged. Without the forge the screen is still correct, just plainer.

What Studio never does:

- **It never decides.** It does not touch control state. It does not start, resume, cancel or merge, and it holds no forge-write credential.
- **It never claims more than the record supports.** A task that stopped reporting is shown as presumed dead, with its silence stated. A pause with no recorded reason claims nothing. Merged appears only where a source outside the Log says so.
- **It never asks the Log to record more.** If a fact is not in the Log, Studio shows less.

## Start Studio

Run Studio from inside a governed repository:

```bash
vinaya studio
```

To choose the port yourself:

```bash
vinaya studio --port <n>
```

```steps
### The launcher finds your repository
Before the server starts, the launcher resolves which repository it is in. It passes the repository (`AEG_REPO`, as owner/repo) and your working directory (`VINAYA_REPO_ROOT`) into the server's environment.

### It finds the Studio app
From a checkout that carries the Studio web app, it runs that (`workspace`). Otherwise it runs the Studio build bundled into the installed `@attalabs/vinaya` package (`package`). If neither is there (`missing`), it refuses and tells you how to install it.

### It picks a port
Studio uses port `3008` by default, or `3108` if `3008` is taken. A port you pass with `--port` is used exactly, or refused; it is never moved.

### It binds to your machine only
Studio listens on loopback (`127.0.0.1`) unless your own `HOSTNAME` says otherwise.
```

```callout-warning
Studio has no authentication of its own. It is safe because it is local and bound to loopback. It holds no forge-write credential and no access to control state.
```

```callout-note
When Studio reads a log server from a browser, the read token is to be held by a backend or a login-gated token route, never shipped in the page. This is planned.
```

## Configuration

Studio has no keys of its own. It reads:

| Setting | What Studio uses it for |
| --- | --- |
| `logs` | Where the Log is: a destination folder, or a server with its `readHeaders` |
| `.vinaya/projects.md` | Read by the dashboard, beside the forge |
| `vinaya.config.json` | The repository's settings |

Both files are read from the repository root Studio was launched in. See [The file and its keys](/docs/features/configuration/the-file-and-its-keys).

## What gets logged

Nothing. Studio reads the Log and never writes to it.

## Troubleshooting

```accordion
### Studio refuses to start and gives an install hint
The launcher found no Studio app: neither a checkout with the Studio web app nor a build in the installed `@attalabs/vinaya` package. Follow the install hint it prints.

### Studio refuses the port I asked for
A port passed with `--port` is used exactly or refused. Pick a free port, or leave out `--port` to get `3008`, or `3108` if `3008` is taken.

### Titles and pull request states are missing
Studio reads the forge only for presentation. Without it, the screen is correct but plainer: you see the facts from the Log, without titles or merge state.
```
