# Goals and milestones — definition

Summary: A Goal is a GitHub Milestone the Architect declares once: goal prose, an optional Release line and the tranches that serve it. Its lifecycle is derived from those tranches.
Parent: Thinking
Badges: Architect · Milestone · Optional · Derived lifecycle

## About Goals

A **Goal** is a product outcome and the tranches that serve it. It lives as a real GitHub Milestone. It is the one level above the tranche, and it is optional: most tranches have no Milestone and need none.

To plan work from a Goal end to end, follow [Deploy complex work](/docs/process/guides/from-a-goal).

## How it works

```steps
### Declare the Goal
The Architect declares the Goal once, naming its tranches up front in `### Tranche intents`. A tranche that already exists can also be adopted later. This is the only stage a human decision truly gates.

### Tranches run
Each named tranche runs its own flow: plan, dispatch, archive. The Milestone does not orchestrate; the Principal or a thin dispatch script decides when each tranche starts.

### Close
When every declared tranche is complete, the Milestone reads `complete`. Cutting a release for the `Release:` version is a separate, largely manual act.
```

When an open Milestone names a tranche's slug, `task_issue_create` attaches each new task Issue to that Milestone by itself. The Planner takes no step.

## The Milestone description

The Milestone's **title** is free text for people. It is never parsed. The **description** carries three parts:

| Part | Required | Grammar | Meaning |
| --- | --- | --- | --- |
| Goal | Yes | Prose: whatever remains once the two parts below are removed | The product outcome |
| `Release:` | No | Line-anchored, `**` optional on both sides, code fences stripped first, first match wins | The only source of the target version. Never the title |
| `### Tranche intents` | No | One bullet per tranche: `- <slug>: <intent text>` | Which tranches serve this Goal and what each contributes |

A tranche's goal is derived, never stored. It is the intent line whose slug matches the tranche's label, found by searching every Milestone's description. An intent line for a slug with no Issues yet is a real tranche in the `planned` state.

```callout-note
A tranche is identified by its `vinaya/tranche:<slug>` label, never by a Milestone. One legacy exception: a Milestone titled exactly with a tranche's slug still means that one tranche. This covers Milestones created before `0.19.0`, when the Milestone layer arrived.
```

## Commands

| Role tool | What it does | Who |
| --- | --- | --- |
| `milestone_create` | Checks the body's shape, then writes one Milestone through the GitHub API | Architect |
| `milestone_edit` | Same check as create, then rewrites the description | Architect |
| `milestone_adopt` | Reattaches every Issue carrying each named tranche label to the target Milestone, then closes (never deletes) each slug's old legacy Milestone | Architect |
| `milestone_status` | Read-only. For each `- <slug>:` line, prints the slug, its derived lifecycle and its Issues' counts (`merged`, `open`, `not planned`) | Architect or Tranche Archivist |
| `milestone_close` | Finds the tranche's Milestone, checks every Issue carrying `vinaya/tranche:<slug>` is attached to it, refuses naming each unattached or foreign Issue, then closes it | Tranche Archivist |

`milestone_adopt` refuses the whole call, before any write, on an unknown slug, a slug with no Issues, a missing or closed target, or a slug already adopted elsewhere.

## Lifecycle

The state is derived from the Milestone's tranches. It is never written to the Milestone.

| State | When |
| --- | --- |
| `planned` | Every named tranche is `planned`, or the Milestone names no tranches |
| `active` | At least one named tranche is `active` |
| `complete` | Every named tranche is `complete`. A Milestone naming zero tranches never reads `complete` |

```accordion
### A closed legacy Milestone still matches its slug
`adopt` closes the old one-tranche Milestone, which still matches its slug by title. When a legacy-matched Milestone is closed and its slug still has labelled Issues, the lifecycle is derived from those Issues, not from the closed Milestone's state.
```

## Roles

| Role | Does | Never does |
| --- | --- | --- |
| Architect | Creates the Milestone, once, with `milestone_create`. Invoked by hand, on demand; no dispatch queue, no brief format | Cut or size a task, decide edges, read a version from the title, write status |
| Planner | Reads the derived goal as context when planning | Edit a Milestone description, treat an intent line as an instruction on sizing or edges, create a Milestone |
| Principal | Sets product direction; the Architect applies goal or `Release:` corrections with `milestone_edit` | — |
| Tranche Archivist | Closes the Milestone at tranche close. See [Tranche and Milestone close](/docs/process/retrospecting/tranche-and-milestone-close) | — |

The Architect refuses when the goal is absent, when `Release:` is present but not a version, when `### Tranche intents` does not parse, or when asked to cut a task, size a task or read a version from the title.

The hand-off from Architect to Planner carries exactly one field: the intent line, matched by slug. It carries no sizing, edges, traps, agent class, stop conditions, documentation list or status.

## Gates

| Gate | When | Refuses |
| --- | --- | --- |
| Milestone shape check | `milestone_create` and `milestone_edit`, before any GitHub call | A missing goal; `Release:` present but not a version; unparseable `### Tranche intents` |
| Adopt check | `milestone_adopt`, before any write | An unknown slug, a slug with no Issues, a missing or closed target, a slug already adopted |
| `issue-milestone-attach` | Issue edit (Ring 1) | On edit, a task Issue whose Milestone is not the one its tranche label resolves to (not checked on create) |
| Attachment check | `milestone_close`, before closing | Any tranche Issue not attached to the Milestone |

No config flag ever turns off the Milestone shape check.

## Configuration

| Key | Effect |
| --- | --- |
| `briefSchema.milestone.sections` | Extra sections a Milestone write must carry. Vinaya's own repository does not set it |
| `principals` | Who may edit a Milestone's goal |

## What gets logged

| Act | Log events |
| --- | --- |
| Every `milestone *` command | `operation` · `completed` |
| An Architect agent turn, when dispatched | `dispatch`, `role_attempt`, `usage` |

There is no pull request to carry the Architect's token count, so it reports tokens wherever it reports back, as `Tokens: milestone — Architect — <model> — in/out/cost`.
