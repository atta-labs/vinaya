# Self-improvement — definition

Summary: The Improver reads the Log across many runs, finds what to change in the process, and proposes it. The Principal approves.
Parent: Features

## What it is

The Log turns every run into a record. Self-improvement learns from it, for every process that writes the Log, not only Vinaya.

```steps
### The Improver reads the Log
A harness agent, the Improver, reads the Log across many runs and finds patterns: where rounds are lost, which gate catches most, what a task costs.

### It proposes a change
Each pattern becomes a proposal: a change to instructions, gates, settings or roles.

### The Principal approves
An approved change becomes a new process version. Runs already in progress keep the version they started with.
```

```callout-note
The Improver is a harness agent, not a process role. The Operator only operates; it never reads the report or proposes changes.
```

## What the record answers

Ten questions, plus a confidence comparison, counted by [Telemetry](/docs/features/telemetry) from the Log:

1. Does a cheaper model finish?
2. Are reviewers strict?
3. What does a unit of work cost?
4. Where does the time go?
5. Does the product catch anything?
6. Which check catches most?
7. Are checks deterministic?
8. Which findings recur?
9. Is the instruction version the problem?
10. What change size converges?

The confidence comparison: does stated confidence predict the review outcome?
