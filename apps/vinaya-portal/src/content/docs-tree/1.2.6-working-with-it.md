# Working with it — definition

Summary: How you, the Principal, use the Vinaya process day to day: three commands in your agent, your rulings, and Studio. The agents do the rest.
Parent: The Vinaya process
Badges: Principal · Slash commands · Rulings · Studio

## About working with it

You drive the Vinaya process from inside your agent, in Claude Code or Codex. Three commands start the agent roles. You decide at a few fixed points, and you watch everything in Studio.

## Run the three commands

```steps
### /vinaya architect
Thinking. The Architect turns product work into one milestone. You decide the parts together.

### /vinaya planner
Thinking. The Planner writes every task as an Issue an agent can run. You approve the plan.

### /vinaya operator
Executing. The Operator dispatches the agents, runs the gates, and stops when it needs you.
```

You do not have to start at the top. Start with the Planner for one feature or one fix. See the [guides](/docs/process/guides/from-a-goal).

## Where you decide

You hold three decisions:

- **Approve the plan.** No task is dispatched before you do.
- **Rule when a run pauses for you.** A pause names who must act. When it is you, post your ruling with `vinaya pr rule`. See [Pauses and rulings](/docs/process/executing/pauses-and-rulings).
- **Merge.** Nobody else merges, and the gates must already be green.

```callout-tip
Infrastructure problems retry by themselves and the Operator repairs the environment. Only policy and scope questions come to you.
```

## Watch it in Studio

Studio is a harness feature that reads the [Log](/docs/features/log). With the Vinaya process it shows every milestone, every task and every review round, live. See [Studio](/docs/features/studio).

## The commands

These are the commands you run yourself in the Vinaya process. The rest are run by the Operator and the agents.

```commands
studio
pr rule
```
