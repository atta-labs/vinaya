# Setup commands — definition

Summary: Four commands put Vinaya into a repository, keep it current and take it out: init installs, doctor diagnoses without writing, upgrade regenerates what Vinaya owns, eject reverses the install exactly.
Parent: Configuration
Badges: init · doctor · upgrade · eject · Diff first

## About the setup commands

`vinaya init`, `vinaya doctor`, `vinaya upgrade` and `vinaya eject` share one engine. Every command that writes shows you the complete diff first and waits for your confirmation.

- Nothing runs when the package is installed.
- `PATH` is never touched.
- Branch protection is printed as a recommendation, never applied.

## How it works

```steps
### Detect
The command reads the repository and `vinaya.config.json` at the repository root. It never walks up to a parent folder, so a nested fixture never picks up an ancestor's config.

### Build the operations
It builds a typed list of the operations it would perform.

### Show the diff
It renders the complete diff. With `--dry-run` it stops here and writes nothing.

### Confirm and apply
After you confirm, it applies the operations.

### Record ownership
It records what Vinaya owns in the `managed` manifest inside `vinaya.config.json`. `upgrade` regenerates only what the manifest lists, and `eject` removes only what it lists.
```

## The commands

| Command | Flags | Writes |
| --- | --- | --- |
| `vinaya init` | `--dry-run`, `--yes`, `--agents=<list\|all\|none>` | Yes, after confirmation |
| `vinaya init product <name>` | `--path <path>`, `--dry-run`, `--yes` | One registry row and one `projects` entry |
| `vinaya doctor` | `--json` | Never |
| `vinaya upgrade` | `--dry-run`, `--yes` | Yes, after confirmation |
| `vinaya eject` | `--dry-run`, `--yes` | Removes, after confirmation |

````tabs
=== init
Installs Vinaya into the repository.

```bash
vinaya init --dry-run
vinaya init
```

**Requires** a git repository and an authenticated `gh`. `gh` is not needed for `--dry-run`, or when there is no GitHub `origin` (label creation is then skipped).

**Refuses** a custom `core.hooksPath`. It never overwrites a file it does not own.

| Group | Files |
| --- | --- |
| Workflows | `.github/workflows/vinaya-checks.yml`, `vinaya-review.yml`, `vinaya-review-verdict.yml`, `vinaya-archivist.yml`, `vinaya-body-checks.yml` |
| Git hooks (managed blocks) | `pre-commit`, `pre-push`, `commit-msg` in `.vinaya/hooks/` (tracked, then `git config core.hooksPath .vinaya/hooks`), or in `.husky/` or `.git/hooks/` |
| Config | `vinaya.config.json`: starter `rings` (both `true`), empty `checks`, starter `briefSchema`, then `managed` |
| Doctrine pointer | `AGENTS.md`, `CLAUDE.md` |
| Doc ownership | `.vinaya/doc-owners` |
| Scaffold folders | `vinaya/checks/.gitkeep`, `vinaya/roles/.gitkeep` |
| `--agents` includes `skills` | `.agents/skills/vinaya-<role>/SKILL.md` |
| `--agents` includes `claude` | `.claude/skills/vinaya-<role>/SKILL.md`, `.claude/commands/vinaya.md`, `.claude/settings.json` and `.claude/hooks/track-transcript.sh` (Stop hook), `.mcp.json` (task-tools server) |
| `--agents` includes `gemini` | `.gemini/commands/vinaya.toml`, `.gemini/settings.json` |
| Labels | Created if absent, never modified (tier, needs, type and other fixed labels) |
| Printed only | Branch protection, CODEOWNERS and `principals` recommendations; a note that agent-native commands need `vinaya` on `PATH` |

The manifest is written as soon as the files are on disk, before the labels, so a label failure never leaves files unowned.

=== init product
Registers a product in an initialized repository.

```bash
vinaya init product <name> --path <path>
```

Needs an initialized repository and a lower-case slug; no forge access. It appends a row to `.vinaya/projects.md` and an entry to `projects`. Neither is recorded in the manifest, so `eject` never removes them.

=== doctor
Diagnoses the install. It never writes; the one exception is a throwaway temporary folder for the sandbox probe.

```bash
vinaya doctor
vinaya doctor --json
```

It replays the same operation list `init` builds, against the disk and the manifest, then reports:

| Area | What it checks |
| --- | --- |
| Config | `vinaya.config.json` is valid; Vinaya is initialized |
| Install drift | Hooks, workflows, config and `AGENTS.md` are present and current |
| Hook routing | Whether git actually runs the hooks in this clone (`core.hooksPath`) |
| Custom checks | Every `checks.*.run` path exists; `env` declarations lint (a literal `"true"`, secret-looking values); check classification |
| Ownership and projects | `.vinaya/doc-owners` health; `projects` agrees with `.vinaya/projects.md` |
| Trust | `principals` is set; the global file carries stripped keys; branch protection; CODEOWNERS over `.github/workflows/**` |
| Brief schema | Divergence from the builtins, silenced by `briefSchema.ack` |
| Environment | `gh` auth and scope, reachability, Node or Bun, version skew between package and installed files, `vinaya` on `PATH`, token metering |
| Tests | A heuristic: does CI run tests |
| Log | The destination the sink would actually use works from this machine (one empty POST to ingest; a schema digest when `readHeaders` is set); the last folder fallback |
| Sandbox | The agent sandbox probe |

Exits `0` when every finding is `ok` or `info`, and `1` otherwise.

=== upgrade
Regenerates the files Vinaya owns from the installed package, with the same diff and confirmation.

```bash
vinaya upgrade --dry-run
vinaya upgrade
```

Your content is never touched. Semantic config fields (`rings`, `checks`, `briefSchema` and the rest) are kept; only `managed` is rewritten. Files Vinaya does not own are left alone.

- Reads the `--agents` selection back from `managed.agents`. An install that never recorded one gets every vendor's files.
- Removes retired files: the collector workflow, the former pointer name `VINAYA.md`, retired role skills.
- Moves `.git/hooks` installs to tracked `.vinaya/hooks` and sets `core.hooksPath`, unless that would silence a hook Vinaya does not own. Then it refuses, and says why on every run.
- Inverts explicit `rings` values once, for configs whose manifest predates version 3.
- Refuses a manifest newer than the package understands, an invalid config, or an uninitialized repository.

`upgrade` is the only sanctioned path back to a clean install.

=== eject
Reverses `init`.

```bash
vinaya eject --dry-run
vinaya eject
```

- Deletes the files Vinaya created, including `vinaya.config.json`.
- Strips managed blocks and keeps your own lines around them.
- Unsets `core.hooksPath` for tracked installs.
- Lists the labels it created for you to remove by hand; it never deletes them.

Refuses, deleting nothing, when the manifest is missing or corrupt, or records a path outside the allowed bounds. On an untouched repository it does nothing. `init` then `eject` returns the repository to its state before `init`.
````

## Configuration

| Key | Used by |
| --- | --- |
| `managed` | All four commands |
| `ci.setup` | `init`, `upgrade`, `doctor` (added to the generated workflows) |
| `briefSchema.ack` | `doctor` |
| `rings` | `upgrade` (the version-3 migration) |
| `projects` | `init product`, `doctor` |
