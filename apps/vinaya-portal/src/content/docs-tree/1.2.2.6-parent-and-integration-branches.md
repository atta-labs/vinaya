# Parent and integration branches — definition

Summary: Every Issue has a parent branch, pinned in its frozen brief: its worktree forks from the parent and its pull request merges into it. An integration branch is a parent shared by several Issues, merged into its own parent through the same gates.
Parent: Executing
Badges: Parent branch · Integration branch · Frozen brief

## About parent branches

Every Issue has a **parent branch**. It is declared when the Issue is planned, carried in the brief and pinned into the run. The Issue's worktree forks from the parent, and its pull request merges into the parent. The default parent is `main`.

An **integration branch** is a branch that is the parent of several Issues: planned, backlog or hot, from any tranche or none. When it is done, the Principal merges it into its own parent through the same gates.

With parent branches, every gate that reads `main` reads the parent instead. See [Tranches and tasks](/docs/process/thinking/tranches-and-tasks).

```callout-note
Parent branches are planned.
```

| Role | Part |
| --- | --- |
| Planner | Declares `**Parent:**` when planning; absent means `main` |
| Principal | Creates an integration branch and merges it into its parent; declares the parent for a hot Issue |
| Controller | Forks, reserves, opens the pull request and measures against the frozen parent |
| Archivist | Closes the Issue when it archives a merge into a parent that is not the default branch |

## How it works

```steps
### Declare the parent
Add `**Parent:** <branch>` to the Issue header. Leave it out to use `main`.

### Freeze it in the brief
The frozen brief records the parent. From then on, the brief is the only source of the parent.

### Fork, work and open the pull request against the parent
The worktree forks from the parent, and the pull request targets it.

### Merge and close
The pull request merges into the parent. If the parent is not the default branch, the Archivist closes the Issue.
```

### The rules

| Rule | Detail |
| --- | --- |
| The field | `**Parent:** <branch>` in the Issue header, beside `**Project:**`. Absent means `main`. The Issue gate refuses a parent that does not exist on the remote, or that equals the Issue's own branch. |
| Pinned, never live | The brief renders `Parent: <branch>` in place of the fixed "parent `origin/main`". The frozen brief is the only source. Changing the parent means superseding the brief, which voids the verdicts. |
| One resolver | A single resolver reads the `Parent:` line of the newest frozen brief. With no frozen brief, the parent is `main`. |
| Plan time | For a parent other than `main`, Issue validation and task preparation fetch `origin/<parent>` and read the premises and Surface globs from it. If the fetch fails, they refuse. |
| Controller and Developer | Every `main` in the loop becomes the frozen parent: worktree creation, the reservation push, the pull-request base, the ahead and fresh-branch checks, the conflict-retry base, and the merge prompt. Doctrine and brief text say `origin/<parent>`. |
| Status | `merged` means merged into the frozen parent (the pull request's base equals it). Detecting a reopen uses the time of the close event. |
| Dependencies | A `Depends-on` is satisfied when the dependency's merge commit is reachable from the dependent's parent tip (`git merge-base --is-ancestor <mergeCommit> origin/<parent>`). |
| Close and archive | GitHub closes Issues by keyword only on the default branch, so the Archivist closes the Issue when it archives a merge into a parent. |

### How each context gets the parent

| Context | Source |
| --- | --- |
| The controller and `task run` | The brief they already hold |
| The check commands, run locally | The resolver, when `BASE_SHA` is unset |
| CI | `BASE_SHA` = `git rev-parse HEAD^1` in a new step of "Run checks". The review gate refuses when the pull request's base differs from the frozen parent. |
| Developer sandbox and reviewers | A new key, `VINAYA_PARENT_BRANCH`, passed to every dispatched role |
| `pr report` Test Plan commands | `VINAYA_PARENT_BRANCH` added to each command's environment |
| `verify-docs`, `verify-task`, `check-no-disk-state`, `open-pr` | `BASE_SHA`, else `VINAYA_PARENT_BRANCH`, else `origin/main` |
| The coherence check | The frozen parent, through the resolver; never an input the pull request can edit |

## Integration branches

```steps
### Create the branch
The Principal creates it with `git push origin main:refs/heads/<name>`. It becomes an integration branch the moment a frozen brief names it as a parent.

### Run Issues against it
Issues with `**Parent:** <name>` run as usual, and their pull requests merge into it.

### Merge it into its own parent
Write a hot Issue whose `## Surface` covers `git diff --name-only <parent>...<integration>`. Run `vinaya hot start --adopt-branch <integration> --issue <m>`, open the pull request with `vinaya pr create --head <integration> --base <parent>`, and review it with `vinaya hot review`.
```

See [Hot mode](/docs/process/executing/hot-mode) and the guide [Deploy hot issue now](/docs/process/guides/hot-issue) for the hot steps.

## What reads the parent instead of main

| Reader | With parent branches |
| --- | --- |
| Premises and Surface globs at plan time | `origin/<parent>` |
| Controller: worktree fork, reservation push, pull-request base, conflict retry | The frozen parent |
| `pr-premise-reassert`, `surface-scope`, `evidence-fresh`, `single-plan-pr`, `doc-coverage`, `doc-coverage-push`, `no-disk-state`, `doctrine-portability` | The resolver, or `BASE_SHA` |
| Merge gate (`review-gate`) | Follows the pull request's declared base, and refuses a base that differs from the frozen parent |
| Status (`merged`) and dependency satisfaction | Merged into the parent; merge commit reachable from the parent |
| `pr report` | The resolver |
| Archivist workflow | `branches-ignore: ['task/**']`, with a pre-filter step |
| Direct-push audit | Every declared parent |
| Log envelope | The landing branch, filled from the frozen parent |

## Gates

The planned changes to the gates:

- **Issue write** refuses a parent that does not exist, or that equals the Issue's branch.
- **`review-gate`** refuses a pull request whose base differs from the frozen parent.
- **The checks that use `BASE_SHA || origin/main`** compute against the parent. Their registry rows gain the optional inputs `BRANCH`, `AEG_REPO`, `GH_TOKEN` and `GITHUB_TOKEN`.

```callout-warning
`surface-scope` is dormant on the integration pull request, because its head is not a task branch. For that one pull request, mechanical scope enforcement does not hold. This is still an open question.
```

See [Gates](/docs/process/gates) for each check.

## Configuration

None. The parent is a field on the Issue, pinned by the brief, not a setting.

## What gets logged

With parent branches, the Log envelope carries the landing branch, filled from the frozen parent. See [Events](/docs/process/events).
